# Crater UI translations

Crater's operator console is fully authored with `qsTr()`, so the whole
interface is translatable. This folder holds the per-language catalogs; the
runtime loader is `app/src/TranslationService.{h,cpp}`, and the picker lives in
Settings → Appearance → Locale.

## What's here

| File | Committed? | Role |
|------|-----------|------|
| `crater_<code>.ts` | ✅ | Human-reviewable translation source (Qt Linguist XML). The source of truth for each language. |
| `crater_<code>.qm` | ✅ | Compiled binary catalog. Bundled at `qrc:/i18n/` by `app/CMakeLists.txt` and loaded by `TranslationService`. |
| `crater_template.ts` | ❌ (gitignored) | Freshly-harvested source strings, no translations. Regenerated by `lupdate`. |
| `_sources.json` | ❌ (gitignored) | Flat list of unique English strings — the translation step's input. |
| `_map_<code>.json` | ❌ (gitignored) | `{ english → translation }` produced by the translation step — merged into the `.ts`. |

`<code>` is a Qt locale (e.g. `es`, `pt_BR`, `zh_CN`) and is exactly the value
stored in `Settings/language`. English is the **source** language — it has no
catalog; `qsTr()` renders the literals directly.

## Runtime behavior

- The chosen catalog is installed **before** the first paint (see
  `main.cpp` → `TranslationService::applyPersistedLanguage`).
- Changing the language is **live** — no restart. `TranslationService` swaps the
  `QTranslator` and calls `QQmlEngine::retranslate()`, re-evaluating every
  `qsTr()` binding.
- Any string missing from a catalog **falls back to English**, so partial
  translations are safe to ship.
- **Drop-in languages:** a `crater_<code>.qm` placed in
  `<AppDataLocation>/Crater/translations/` is picked up at the next launch and
  appears in the picker automatically — no rebuild. (On Windows that's
  `%LOCALAPPDATA%\Voyager Labs\Crater\translations\`.)

## Regenerating / adding languages

Everything is driven from `tools/i18n/` (`languages.json` is the master list).

```sh
# 1. Harvest translatable strings from QML (qsTr) + C++ (tr) into the template.
lupdate -locations none -no-obsolete -recursive app/qml app/src -ts app/i18n/crater_template.ts

# 2. Flatten the template to the unique source list.
python tools/i18n/extract_sources.py app/i18n/crater_template.ts app/i18n/_sources.json

# 3. Produce app/i18n/_map_<code>.json for each language (the translation step).
#    Hand-authored, professional, or AI-assisted — any tool that writes the
#    { english → translation } JSON works.

# 4. Merge maps into crater_<code>.ts for every language in languages.json.
python tools/i18n/build_catalogs.py

# 5. Compile the .ts into the bundled .qm.
python tools/i18n/build_qm.py            # add --lrelease <path> if not on PATH
```

**To add a language:** append it to `tools/i18n/languages.json`, add the same
`{code, english, native, rtl}` row to `kKnownLangs` in
`app/src/TranslationService.cpp`, list `i18n/crater_<code>.qm` in
`app/CMakeLists.txt`, provide a `_map_<code>.json`, then run steps 4–5.

**To add a handful of new strings** (e.g. after new `qsTr()`/`tr()` calls)
without re-translating everything: run steps 1–2, translate only the new
strings into `app/i18n/_map_addendum.json` shaped as
`{ "<english>": { "es": "…", …, "ar": "…" } }`, then
`python tools/i18n/apply_addendum.py` (folds them into every `_map_<code>.json`)
and run steps 4–5.

**To fix a translation by hand:** edit `crater_<code>.ts` directly (in Qt
Linguist or a text editor) and run step 5.

## Notes

- The bundled translations are AI- and community-assisted. English is
  authoritative; corrections are welcome as `.ts` edits.
- **RTL:** Arabic (`ar`) text renders right-to-left inside its fields, but the
  console layout is not yet mirrored (`LayoutMirroring`). Full RTL layout is a
  follow-up — see `docs/TODO.md`.
